# Current design brief — GitHub Issues review

## User direction

The previous three directions were rejected as cluttered and containing too many
visible elements. The user supplied https://github.com/addyosmani/agent-skills/issues
as the interface reference and explicitly retired the Huashu design process.
Implement one focused revision, rather than another three-direction selection.

## Reading model

The default view is an issue list with native system typography, white surfaces,
thin gray borders, compact rows, and restrained semantic labels. A small repository
breadcrumb identifies the research project. A left navigation provides Issues,
Overview, Review history, and Sources. The default page shows one short assessment
line, search, state/severity filters, and grouped concerns. It carries no decorative
artwork, giant verdict typography, score dashboards, or simultaneous document columns.

Selecting an issue opens a separate discussion view. Reviewer concern, author
rebuttal, and final reassessment appear sequentially, with original sources behind
small View source controls. A narrow context column carries severity, original
reviewer IDs, the closure criterion, and evidence links. Search/filter state should
survive returning from detail and reloading within the tab where storage permits.

## Content and behavior

Use the existing true projection-review test case and preserve all 18 bundled
original source texts and hashes. The actual recommendation is Kill; the frozen
proposal is unchanged; novelty and runtime remain unassessed; the conditional
benchmarks were canceled. Keep issue statuses distinct from human feedback.

Preserve source inspection, local annotations, editing/deletion, unfinished draft
recovery, and Markdown export. Keep storage status quiet when available and visible
when storage is blocked. Overview, review history, and sources contain the full
context on demand. All interface text is English; comments preserve user wording.

Deliver one self-contained offline file, github-review.html, with list and detail
screenshots at 1440×900 and 1024×768. Verify functionality, contrast, overflow,
source fidelity, and absence of runtime network dependencies. Earlier variants
remain archived as prior explorations. Automatic skill integration is subsequent.
