# Final research handoff

Render every persisted run, including negative/incomplete outcomes:

```bash
python3 <skill-dir>/scripts/research.py render research/<slug>
```

Deliver links to `final/review.html`, `final/paper.md` when available, the final
report and workspace. State the target year/track, evidence stage, execution mode,
actual outcome, completed/allowed rounds and unresolved scientific uncertainty.
A pending role or budget stop is not acceptance. A proposal is not measured work.

The report is an index into the full journal-backed UI. In the user-facing
handoff explain the final idea, core insight, precise novelty against closest
work, expected contribution, high-level mechanism and decisive falsification
experiments. Identify the largest rejection risk, first implementation task,
resource assumptions and remaining uncertainties. Link detailed evidence instead
of copying all reviews into the answer.

The complete paper contains all required academic sections and explicitly
hypothetical predicted-result ranges, assumptions, rationale and failure cases.
Use the selected frozen submitted version, never an unreviewed last-minute edit
presented as accepted. Unsubmitted proposals must remain labeled unsubmitted.
The UI preserves every actual paper version and comparison, including rejected
novelty attempts, rebuttals, original/updated scores, discussions, chair reasoning
and motivating revision concerns.

If real independent chairs did not participate, say so and deliver self-critique
or pending packets. Never invent chair recommendations or claim independent
convergence from one context. A simulated Accept indicates apparent competitiveness
under the reconstructed process and does not guarantee real acceptance.

For hosts without execution/file tools, deliver actual completed content inline
with an exact continuation checkpoint and explain which outputs remain pending.
Do not claim saved files, independent reports or experiments that do not exist.
